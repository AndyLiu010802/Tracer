# Tracer 账户与壁纸商店 · 开发规格草案

## 用户体验

用户完成任务，收获并出售植物得到「花园金币」，在「风景商店」预览壁纸，确认购买后永久收藏到 Tracer 账户。个人资料 → 外观 → 我的收藏支持随时切换；退出登录后不让其他账户看到或使用上一个账户的私人收藏记录。

商店入口：现有「收获仓库」旁增加「风景商店」；右上角账户菜单增加「我的外观」。商店有静态、动态、材质三类，以及已拥有、心愿单筛选。每个商品标注价格、全屏预览、实际动态/材质效果、已拥有/使用中状态。

用户可免费预览所有款式。正式购买时展示商品名称、价格、当前余额和购买后余额；只有点击「确认购买」才扣款。购买成功后显示「已加入收藏」与「立即使用」。重复购买返回已拥有，不再次扣款。余额不足显示还差多少金币，并提供返回收获仓库的入口。

购买为花园虚拟金币，不设计现金购买、租赁、盲盒、随机抽取、限时失效、排行榜或社交公开。本期账户资料与收藏默认私有。

## 两个独立外观槽

- `backgroundItemId`：静态或动态壁纸，互斥。
- `materialItemId`：界面材质，可与壁纸叠加。
- `appearancePreferences`：遮罩深度、动态强度、暂停动态、是否跟随账户外观。

材质购买默认包含其配套背景。用户可点「应用整套」同时替换两个槽，或只应用材质保留现有壁纸；切换前明确显示影响范围，避免覆盖用户搭配。恢复默认外观不删除任何已购内容。材质内的配套背景权益由材质商品授权，不需要再买另一件商品。

产品名称上保留用户的三种分类，但数据结构将背景和界面材质分开，方便未来自由搭配。服务器验证每个槽的商品类型和账户权益。

## 账户一期衔接

账户功能：邮箱登录/找回、个人头像昵称、游客数据迁移、设备会话管理、账户数据导出与删除、任务/笔记/花园/收藏同步。Tracer 账户与 AI 服务连接分别管理。

登录前可以离线工作和预览。首次购买需要登录，以便把权益归属到具体账户。已有游客金币和种植记录在登录时展示迁移预览并明确归属；迁移以唯一凭据防止同一批历史收获重复导入或导入多个账户。正式迁移政策需随账户实现一起完成，不直接信任客户端提交的余额。

已下载且已验证拥有的壁纸可以离线继续使用。购买必须联网；本机账户缓存分区存放，退出登录清除登录凭据与账户界面状态。另一账户登录后只加载其自己的权益。公共静态素材本身不是敏感信息，不能把「账户绑定」描述为不可复制的 DRM。

## 现有经济的衔接

当前 `skins/tracer/task-garden.js` / `public/task-garden.js` 使用 market version 1，出售植物单价为 12、18、20、25、30、28、32、36、40，赛博农场价格 240。余额通过销售记录减农场购买记录计算；购买校验器只接受既有农场。

因此不能只给界面增加一个按钮或单独减少余额字段。应引入新版统一金币账本，同时记录农场与壁纸支出，迁移原销售/购买记录，并更新双方验证、同步冲突处理和历史读取。历史成交价保存在交易快照，未来改目录价格不能改变过去的余额。

草案价格：静态 60–100，动态 140–220，材质 240–360。依当前植物单价，约对应 2–9、4–19、6–30 株的售出收入；实际成本受植物种类和是否已有金币影响。本轮不改变现有作物价格。

## 推荐记录结构（待后端实现）

| 记录 | 关键字段与约束 |
| --- | --- |
| accounts | id、邮箱、昵称、头像引用；稳定内部 id 与可修改昵称分开 |
| wallpaper_catalog | item_id、type、version、price、active、asset_manifest、theme_id、motion_id；价格由服务端决定 |
| wallets | account_id、balance、revision；余额非负，服务端更新 |
| coin_transactions | transaction_id、account_id、signed_amount、reason、source_id、price_snapshot、created_at；来源唯一，历史不可变 |
| wallpaper_entitlements | account_id、item_id、purchase_transaction_id、acquired_at；account_id + item_id 唯一 |
| appearance | account_id、background_item_id、material_item_id、preferences、revision；服务端检查拥有和类型 |
| migration_receipts | source_workspace_id、account_id、source_event_id；一次迁移与原事件去重 |

确认购买请求只传商品 id、幂等键与目录版本。服务端从登录会话确定账户，读当前价格，在一个数据库事务内锁定/条件更新钱包、扣款、记录交易并创建权益。账户+商品唯一约束与幂等请求结果共同保证重复点击、重试、两个设备同时购买不会重复收费。

目录版本或价格变化时返回最新报价供重新确认；不能在用户看到旧价格后自动按新价扣款。扣款与发放权益要么一起成功，要么一起回滚。请求超时后用同一幂等键查询/重试，并返回已完成结果。新建幂等键购买已拥有商品同样不收费。

资产下载校验 manifest 哈希，完整落盘后再启用。更新或下架商品保留已购记录与可用版本，不删除用户收藏。外观同步用 revision 处理冲突，云端失败时保留本机当前外观和可重试提示；不能用一个 last-write-wins 余额覆盖所有设备交易。

## 开发与验收顺序

1. 本轮完成：30 款设计、真实动态效果、材质任务页预览、稳定目录与建议价、原图和提示词、独立画廊。
2. 应用外观基础：两个槽、默认恢复、全页面变量覆盖、可读性、响应式布局、键盘焦点、低性能与减少动态适配。
3. 账户与同步：身份、设备会话、账户存储隔离、游客历史迁移、导出/删除、已拥有集合。
4. 统一金币账本与真实购买：迁移旧记录、购买事务、幂等、余额不足、价格变化、并发、失败恢复。
5. 交付验证：真实应用中切换全部 30 款；购买/重启/重新登录/换设备/离线后权益保持；账号 A/B 隔离；原农场购买和已有余额保持一致。

当前原型只验证设计交互与绘制，不代表后端、登录、扣款或跨设备同步已经上线。
