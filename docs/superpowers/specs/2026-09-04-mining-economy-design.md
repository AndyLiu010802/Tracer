# 开采经济闭合：矿石可售 + 冶炼挂机化

日期：2026-09-04
皮肤：`skins/db-console/`（键盘农场）
标杆：Melvor Idle
前置：`docs/superpowers/specs/2026-09-04-mining-design.md`（开采子系统已完成）

## 背景

开采子系统做完后，最终验收审查指出两个功能缺口。按 Melvor 惯例逐条判断：

**1. 矿石与锭没有第二个出路。** 目前只能锻装备，30 件锻完开采就只剩刷 xp。Melvor 里 ore 和 bar 都是标准可售商品，Bank 里任何物品都能卖，bar 因为加工过比 ore 值钱。**该做。**

**2. 冶炼要点 35 次才能凑齐 T6 一套。** 原本打算加个「炼 ×5」按钮，但这是在错误的方向上优化 —— **Melvor 的 Smithing 根本不是「点一次做一个」，它和 Mining 一样是挂机技能**，选定配方后持续制作直到材料耗尽，而且同一时刻只能训练一个非战斗技能。所以正确的做法不是批量按钮，而是把冶炼改成与开采互斥的挂机活动。**该做，且改的是机制不是 UI。**

这个改动还顺带强化了开采的决策张力：原本只有「挖矿 vs 挖煤」，现在变成「挖矿 vs 挖煤 vs 冶炼」三选一 —— 这正是 Melvor 挂机节奏的核心。

## 一、矿石与锭可出售

### 定价

`ORES` 与 `BARS` 各加一个 `price` 字段。锭的定价高于其原料成本（成本 = 同档矿×3 + 煤×档位），加工溢价约 1.35~1.43 倍 —— 与 Melvor 一致：炼锭本身就是一条有正收益的产业链，不只是锻造的中间步骤。

| 矿石 | price | | 锭 | 原料成本 | price |
|---|---|---|---|---|---|
| `burn_seg`（煤） | 1 | | — | — | — |
| `heap_ore` | 2 | | `heap_bar` | 7 | 10 |
| `fsm_ore` | 5 | | `fsm_bar` | 17 | 24 |
| `vm_ore` | 10 | | `vm_bar` | 33 | 46 |
| `brin_ore` | 20 | | `brin_bar` | 64 | 88 |
| `tblspc_ore` | 40 | | `tblspc_bar` | 125 | 172 |
| `void_ore` | 75 | | `void_bar` | 231 | 318 |

**这版数值是对上一版的修正**：最初按单价对齐鱼价（鱼常见 26–45、传说 500+），实测挂机一小时后开采的金币效率是钓鱼的 7.5~10 倍，与「可比但不压倒」的意图不符。根因是**单价对齐忽略了吞吐差**——开采挂机产出（约 300~1100 块/小时，视矿脉档位而定）是钓鱼自动回收（约 12~40 条/小时）的 18~90 倍，且开采零前置投入（钓鱼要先付鱼塘 5,000 + 回收器 30,000 + 钓点最多 200,000），也不与钓鱼互斥，是纯增量收入。正确的对齐口径是「每小时产出 × 单价」而不是单价本身，按此口径整体下调 6 倍后，零投入 Lv1 挖 `heap_seam` 约 1,500 金币/时、Lv31 挖 `block_void` 约 23,000 金币/时，分别对应钓鱼 `wal_buffer`（1,712/时）与 `pitr_abyss`（17,067/时）的约 0.9 倍与 1.4 倍——落回「可比但不压倒」的区间。开采的主线价值仍是供给锻造。

### 出售入口

沿用仓库既有惯例：**每类物品在自己的 tab 里卖，`sellall` 跨类一键卖，都可锁定保护**（作物在仓库页、鱼在鱼护表，各有 `data-act="sell"` / `"sellfish"` 与 `lock` / `lockfish`）。

- 矿石：`mineTab()` 的库存表加「单价 / 合计 / 卖出 / 锁」四项
- 锭：`forgeTab()` 的熔炉表加「卖出 / 锁」
- `sellall`（仓库页的「一键全卖」）纳入矿石与锭，锁定的除外

锁定 key 沿用现有前缀式命名：矿石 `'o:' + key`、锭 `'b:' + key`（现有是作物裸 key、鱼 `'f:' + key`）。

## 二、冶炼改成挂机活动

### 机制

- 新状态 `state.smelt = { bar: null, last: 0 }`
- **与开采互斥**：开炼时清空 `state.mine.vein`，选矿脉时清空 `state.smelt.bar`。同一时刻只有一个活动在跑，与 Melvor「同时只能训练一个非战斗技能」一致
- 冶炼间隔固定 `SMELT_MS = 2000`（Melvor Smithing 的基础间隔），**不吃 agi** —— agi 是开采的效率维度，冶炼保持固定节奏，两者的加成不叠在一起
- 每个间隔消耗一份配方（同档矿×3 + 煤×档位），产 1 锭，给 `SMELT_XP[tier]`
- 材料不足时自动停止（`bar` 置 `null`），不空转
- 离线结算同样带 `OFFLINE_CAP`（常量与 `settleMining` 共用同一个 2000），但截断口径不同：`settleSmelt` 按固定 `SMELT_MS`（2 秒）轮次计数，2000 轮的等效离线上限约 67 分钟；`settleMining` 的 `guard` 计的是 while 循环迭代次数而非产出次数——矿脉枯竭后进/出再生 CD 各占一次不产出的迭代，同样 2000 次迭代对应的真实时长因矿脉而异（agi=0 基准下，约 139 分钟起、最慢矿脉约 428 分钟；agi 越高间隔越短，上限相应更短）。是否统一成时间上限（Melvor 全技能统一按 24 小时截断）留作后续设计决定，这里先把表述改准

### 模块 API

`mining.js` 新增：

```js
SMELT_MS                                    // 2000
settleSmelt(smelt, state, now) -> { bars: {k:n}, xp, ticks, smelt, stopped }
```

`settleSmelt` 是纯函数，但需要读 `state.ores` 判断材料是否够 —— 它**不修改** `state`，只返回「本次炼出了多少、消耗了多少」，由 `farm.js` 落账。`stopped` 标记材料耗尽导致的自动停止，供 UI 提示。

消耗量由 `smeltRecipe()` 派生，不重复定义配方。

### UI

- `forgeTab()` 熔炉表的操作列：材料够且未在炼 → 「开炼」；正在炼这一条 → 「冶炼中」+ 停止链接；材料不够 → 禁用
- 正在冶炼时，`forgeTab()` 顶部显示当前进度（还能炼几个 = 材料够炼几轮）
- 两个 tab 互相提示当前活动：在开采页挂着矿脉时，锻造页提示「正在开采，开炼会停下矿脉」；反之亦然
- 去掉原来的瞬时 `doSmelt` 点击炼一个

## 三、存档迁移

`migrateMining` 补 `s.smelt = { bar: null, last: now }`；`bar` 指向不存在的锭 key 时清成 `null`（对齐已有的 `mine.vein` 损坏清理）。老存档没有该字段即视为「没在冶炼」，行为不退化。

## 四、伪装

矿石/锭的售价与出售按钮全部走 `state.real ? 中文 : 黑话` 双套名，伪装模式不出中文不出 emoji —— 与现有出售 UI（作物/鱼）一致。

## 五、测试

`test/mining.test.js` 追加：

- `ORES`/`BARS` 的 `price` 齐全且为正；锭价高于其原料成本（用 `smeltRecipe` 算成本，防止改价改出负收益）
- `settleSmelt`：按间隔产锭并扣料、材料不足时停止并置 `stopped`、离线上限截断、`bar` 为 null 或未知 key 时优雅无操作、不修改入参 `state`
- `migrateMining` 补 `smelt` 字段 + 损坏 `bar` 清理 + 幂等
- 互斥：开炼清 `mine.vein`、选脉清 `smelt.bar`（这部分逻辑在 `farm.js`，用纯函数层能测的部分覆盖）

## 六、验收

- 全量测试绿
- 伪装模式下开采页与锻造页无中文泄漏
- 老存档加载不崩，没有 `smelt` 字段的存档视为未在冶炼
- 开采与冶炼真正互斥：开炼后矿脉停止产出，选矿脉后冶炼停止
- 矿石与锭能卖出金币，锁定的不被「一键全卖」带走
