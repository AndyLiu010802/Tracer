# 整体流畅度检查 · 2026-10-12

本轮在 0.4.4 源码基础上优化日常操作和重复工作。使用独立测试工作区与合成存档，不读取用户账户、任务、金币或收藏。没有更改鱼获价格、抽取概率、保底、鱼类模型精度或动画画质。

## 调整

- 看板搜索、优先级和日期筛选移动并复用已创建的任务卡片，保留输入框、光标、事件和拖拽容器。清空筛选复用原节点；真实数据、项目和语言变化仍完整刷新。
- 中文组合输入期间不提前筛选，组合输入结束通过事件监听更新，随后的同值输入事件不重复执行。
- 超过 100 项任务的看板启用屏幕外卡片延迟布局，浏览器滚动到卡片时恢复真实布局并记住高度。任务仍在 DOM 中，保留搜索、键盘访问和编辑。样式限定在当前看板容器，避免切换小项目时先展开旧大看板。
- 钓鱼展示快照在一次完整校验后计算渔场、图鉴进度和水族箱，共用一次余额读取。派生函数保持私有，没有跨调用缓存；账户切换、原地修改和非法记录继续由原验证逻辑处理。
- 鱼塘与水族箱的投喂倒计时使用已接受的展示快照，不再每两秒扫描整个收藏账本；隐藏窗口、失效账户、账户切换和进行中的钓鱼不会触发该展示刷新。
- 鱼竿和鱼类图集的 HTTP 缓存验证先比较文件信息，未变化时直接返回 304，不重复读取大 PNG 和计算哈希。缓存只存有上限的元信息；文件替换后重新计算内容 SHA-256。

## 同机测量

Windows x64，Electron 44.3.0，固定 1000×720 窗口；500 项任务、10 个项目、500 条专注历史。每项操作重复五次，使用事件到第二个动画帧的中位时间。

| 操作 | 修改前 | 最终源码有效样本 |
| --- | ---: | ---: |
| 搜索，500 项到 100 项 | 158.6 ms | 13.7 ms |
| 清空搜索，100 项到 500 项 | 295.9 ms | 20.6 ms |
| 筛选单项目，500 项到 50 项 | 94.1 ms | 48.3 ms |
| 返回全部项目，50 项到 500 项 | 187.9 ms | 44.0 ms |

搜索和清空筛选的完整看板替换次数从每次 1 次降为 0 次。120 次礼包抽取的合成收藏中，一次展示快照的 Node 测量中位时间为 2.45 → 0.96 ms（15 次采样）。这不是整应用 CPU 或所有设备帧率的保证。

原始数据：`.cache/b09-performance-KW4duO/report.json`（修改前四项）、`.cache/b09-performance-o3PNYD/report.json`（最终四项）、`.cache/fluidity-model-before.json`、`.cache/fluidity-model-after.json`。这两份原生采样后来分别在隐藏状态检查和下一操作的可见性检查中停止；表中只引用此前已完成、经过可见性断言的操作，不把整个报告算作通过。

两次完整原生生命周期采样位于 `.cache/b09-performance-mVkkwk/report.json` 与 `.cache/b09-performance-v6sO4D/report.json`。已验证最小化、托盘隐藏、恢复和后台专注只结算一次；最终一次完整样本中，隐藏到托盘时每三秒渲染主线程任务中位时间为 20.62 ms。这些测量来自相同窗口生命周期代码，后续只调整了看板样式作用域与中文组合输入监听。
