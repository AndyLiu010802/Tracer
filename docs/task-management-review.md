# 任务管理体验改进 / Task management review

任务管理交互与字段说明。源码验证方法见文末；当前安装包与发布记录见仓库首页。

## 对照依据

- [Linear：看板布局](https://linear.app/docs/board-layout)：按状态等属性组织任务，支持拖动。
- [Linear：显示选项](https://linear.app/docs/display-options)：可呈现负责人、优先级、估算、标签、截止日期等属性。
- [Asana：任务](https://asana.com/features/project-management/tasks)：负责人、描述、日期、子任务、依赖关系、评论、文件和自定义字段。
- [Asana：项目视图](https://asana.com/features/project-management/project-views)：卡片显示关键任务信息，提供不同工作视图。

这些文档用于比较功能范围。本次抓取手柄、落点占位、取消及撤销方案是针对 Tracer 现有界面的设计判断，并非对竞品界面逐项复刻。

## 已补齐

| 原有差距 | 当前行为 |
| --- | --- |
| 卡片看不出能否拖动 | 常驻 ⋮⋮ 手柄、抓取光标、悬停边框、操作说明 |
| 拖动时无法预测落点 | 跟随指针的卡片、插入占位、目标列高亮、目标状态文字；边缘限制防止提示完全移出窗口 |
| 操作后反馈不足 | 移动结果提示、12 秒内撤销；撤销只恢复移动相关字段，保留其他编辑 |
| 误拖或无法使用鼠标 | Esc / 移出区域取消；Alt + 左右移动状态，Alt + 上下排序；卡片状态菜单 |
| 内容过少 | 任务类型、4 档优先级、负责人姓名、标签、预计/实际工时、描述、验收标准、执行清单、参考链接、前置任务、创建/修改时间 |
| 完成条件模糊 | 可勾选清单与进度、验收标准、未完成前置任务提示；拒绝循环依赖 |
| 表单难以组织 | 两栏详情窗口、窄屏单列、固定保存区域、Ctrl/⌘ + Enter 保存 |
| 误关丢失编辑 | 桌面详情窗口关闭时提示未保存修改，校验失败保留表单 |
| 搜索范围有限 | 可搜索标题、描述、编号、负责人、标签和验收标准 |
| 新字段保存丢失 | 桌面模型和本地工作区保留任务属性、清单与依赖关系 |

桌面看板和任务详情支持中文 / English。拖拽的浮动卡片和落点反馈也适用于日程视图。

## 使用方法

1. 保存当前页面中的编辑后刷新应用。
2. 拖动卡片左上角 **⋮⋮**，看到目标列和占位后松手；按 **Esc** 取消。
3. 移动结果提示中的 **撤销** 可恢复刚才的位置。
4. 点击卡片标题打开详情，填写任务属性、验收标准和执行清单。
5. 选择前置任务后，卡片会显示尚未完成的前置任务数量。此提示不会强制禁止用户完成任务。

## 与完整团队产品仍存在的差距

- 负责人目前是姓名信息，没有成员目录、权限、指派通知或多人协作身份。
- 执行清单属于当前任务，尚不是拥有独立负责人、日期的子任务。
- 工时为手动填写，尚无后台计时器。
- 提供参考链接，尚无附件上传、评论线程、自定义字段、周期任务及自动化规则。

## 验证

- `node --test test/*.test.js`：覆盖任务模型、本地读写、合并冲突和旧数据兼容。
- `dev/qa-task-interactions.js`：浏览器交互验证脚本，所有任务和状态接口都由内存模拟，禁止向任务服务器写入测试数据。
- 独立无界面 Edge 浏览器的 22 项检查通过：详情保存和重开、富字段保留、关闭保护、循环依赖报错、拖拽预览/落下/撤销/Esc/无效落点、指针列内排序、键盘排序及状态菜单、中英切换、日程拖拽及撤销，无页面运行时错误。
- 可选启动脚本：`node dev/run-task-ui-qa.cjs`。需要已安装的 Playwright（或用 `TRACER_QA_PLAYWRIGHT` 指定已有模块目录）、Edge，以及 8097 端口的独立测试服务。任务与状态 API 始终使用内存模拟响应。
- 浏览器交互使用模拟网络响应，不改动真实任务数据。
