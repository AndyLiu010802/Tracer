# 伙伴动作与自动活动

六个内置伙伴，以及九种植物精灵的普通、闪光形态，每个角色形态 16 个动作。现有素材共 384 张动作图、6,144 张原画；播放器现在使用每动作 32 帧，增加局部姿态补间，原始 PNG 不变。补间不是新生成的独立原画，也不会增加原图没有的语义细节。

内置伙伴保留原有像素角色特征，使用独立绘制的待机、摸摸、吃点心、玩耍、睡觉、醒来、专注、拖动、钓鱼、锻炼、种植、采矿、阅读、写字、手作和喝茶动作。原有 SVG 角色仍作为图片加载失败或素材不完整时的后备显示。

植物精灵保留挥手、散步、跳跃、浇水等现有 16 个动作。自动钓鱼、锻炼、种植和采矿会同时显示本地活动场景，不依赖已删除的农场、战斗系统，也不产生资源或奖励。休息、专注、互动和拖动时暂停，解除后等待原有的安静间隔再恢复。

素材通过内置 image_gen 工具生成，原始 PNG 与透明通道直接保存，不通过复制四张图、整体平移或程序补帧来凑满十六帧。普通、闪光形态分别绘制。提示词见 `dev/companion-art-generation-v3.json`、`skins/tracer/pet-art/GENERATION-V1.json` 和 `skins/tracer/garden-art/COMPANION-MOTION-V3-PROMPTS.json`。最终动作图位于 `skins/tracer/pet-art/` 与 `skins/tracer/garden-art/`。

图集构建读取实际 PNG 尺寸、透明间隔和每帧边界，并从最大的连通主体识别身体中心和脚底。所有动作都对齐同一站位，跳跃和散步也原地表现；同一角色在切换动作时保持统一像素比例，不按道具大小重新缩放。原 PNG 像素不改写。图集只收录通过检查的素材，内置角色只有全部十六组齐备时才切换到新播放器。

两个窗口共用播放器。图片按需加载，隐藏、离开可见范围或减少动态效果时停止计时；图鉴重绘和窗口关闭时释放播放器引用。动作预览可直接从伙伴面板展开，不改变需求或奖励。

动作按正序循环，不往返倒放。六个内置伙伴的旧钓鱼图包含放回水中的收尾，因此播放在各自提起收获的帧结束，停留 1.2 秒后开始下一轮；预览也使用相同终点。植物精灵附加场景中的鱼和晶石在抬起后淡出，再于隐藏状态重置。其他动作保留完整的正序帧；生成新动作时明确要求收尾不能撤销钓鱼、采矿、翻页或手作的成果。

内置角色待机先静置约 6 秒，短动作在起止姿势分别停留约 2.2 秒和 1.8 秒，中间帧以 120–140 毫秒推进。`companion-inbetweens.js` 在固定身体中心、脚底和像素比例后，根据局部像素对应关系计算相邻原画的过渡姿态；保留单幅画面的颜色和透明轮廓，不交叉淡化两张脸。补间按需缓存，随图集缓存淘汰。SVG 后备角色改为 32 个关节姿态。钓鱼在成功收获前的原画区间中采样 32 帧，不播放放生结尾。

新建照片伙伴（人型和生物）采用 `animationVersion: 3`：每动作 32 张生成帧，8 列 × 4 行、2048×1024 PNG，共 16 个动作、512 帧。生成、订阅服务、API、任务记录、预览、编辑参考裁切和导入导出使用相同布局。旧版 4 帧／16 帧伙伴继续按原格式读取；已有 16 帧草稿及其单动作重画保持原格式，避免丢失已完成图像。

玩家开始生成前必须填写玩耍道具，以及手作内容与材料；其余动作可分别填写说明。所有说明随恢复草稿保存，对应动作请求携带自己的说明；修改后重画仍只替换选中动作。新格式的服务端也拒绝缺少说明的玩耍／手作请求。

生成提示要求单一缓慢动作、细分过程、固定比例和站位。像素检查保留空帧、不透明背景、切边、重复静图与极端帧间跳变检查，允许正常停顿和肢体接触带来的面积变化。不再把其他动作的连通主体面积与待机图直接比较：坐下、睡觉、手部或道具接触会改变连通面积，旧比较容易误判为生成失败。个人 API 图像请求超时从 180 秒延长为 300 秒。检查不能保证五官相似度或理解动作语义；真实服务仍可能出现额度、网络或模型错误。

32 帧布局使用的自定义尺寸符合 [OpenAI 图像生成接口文档](https://developers.openai.com/api/docs/guides/image-generation) 的尺寸约束。其他兼容服务需要支持所选图像模型和尺寸。

动作描述不作为任务清单执行。生成规则要求先提取与所选动作相符的一个核心动作，舍弃其余活动、表演和道具；全部帧只刻画同一动作的准备、执行和收尾。例如种植描述中的挖土、播种、浇水、庆祝只保留一次浇水。性格只调整核心动作的节奏与表情，不额外添加摇尾、眨眼或转头。每格只画一个人物的一瞬姿态，禁止叠加多重姿态、额外肢体或在人物内部嵌套帧图。

首次生成与单动作重画遇到质量错误时，自动追加最多 2 次请求，重试只针对当前动作，已完成动作不重画。每次新尝试先写入恢复草稿；网络、读图、凭据、额度和存储错误不会触发新的付费尝试。界面明确提示自动重试会使用图像额度。
