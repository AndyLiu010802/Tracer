# 钓鱼布局与桌面流畅度修复

> 旧弹窗验证入口已退役；本文中的相关命令为历史记录。当前验证方式见 [桌面与原画验证](fishing-live-species-upgrade.md)。

本次保留鱼种、鱼竿、模型细节、阴影、特效和权威钓鱼规则，优化显示生命周期、重复计算与数据传输。

- 饵料的 PNG 与 SVG 共用明确的展示尺寸，修复装备栏图片越界。游戏根元素使用 `border-box`；按窗口高度安排池塘与收线条，进度条隐藏时保留空间，防止阶段切换把整个居中面板推上推下。
- 原生透明窗口仅在从隐藏变为显示时调用 `showInactive()`，不再随每次钓鱼状态同步重复显示。初次账户数据到达不再重载一个尚未展示账户内容的页面；后续账户切换继续隐藏并重载，保留输入凭据隔离。
- 桌面鱼塘收到真实钓场状态才创建模型，避免先构建草地、随后拆掉并重建。收起后停止向隐藏窗口发送快照，开启 Electron 的后台节流；重新打开前发送最新状态。
- 在主页面、进入 IPC 之前裁剪快照，移除完整收藏账本、图鉴、成就等。帧更新复用最近一次库存刷新时的金币余额，交易时仍由原有模型重新验证。
- 鱼塘复用不变的显卡材质状态、网格绑定与颜色；缓存岸边高度，同一画面内复用鱼的骨架位置。每帧继续绘制全部模型与动态阴影，没有降低几何精度或纹理分辨率。
- 鱼竿动作在高刷新率屏幕上按最多 60 Hz 更新，使用真实经过时间与余量累计；抛竿输入和阶段切换立即唤醒。桌面未召出的鱼竿停止自己的动画循环，鱼塘继续正常游动。
- 实时鱼竿只创建渲染器所需的 SVG 几何锚点，不再同时加载收藏图集。桌面使用单根鱼竿时不再请求 3000×13000 的完整鱼竿 PNG；该整图 RGBA 像素体积约 149 MiB，实际进程内存节省取决于浏览器解码与缓存策略。收藏预览仍保留。
- 装备文字与天气格式化仅在相关数据变化时更新。

## 验证

`dev/qa-fishing-smoothness.cjs` 使用真实完整主界面和桌面页面、真实动画时钟、模拟存档与原生桥，不读取玩家存档。4 秒稳定场景记录见 `output/fishing-smoothness/before.json` 与 `complete.json`：主界面 RAF 回调脚本累计用时约 1287 → 783 ms；桌面约 1603 → 682 ms。这是测试环境中的动画脚本开销，不是整机 CPU 占用率或原生窗口帧率保证。长期任务统计按采样开始时间过滤，避免把异步送达的启动记录计入稳定阶段。

`dev/qa-fishing-render-cache.cjs` 对九种钓场、每塘五条鱼进行缓存开启/关闭的同帧像素比较，九项最大通道差均为 0。鱼塘切换与 GPU 资源释放验证通过。800×700、1024×600、390×760 的窗口检查中，抛竿按钮可见，无横向溢出。

`dev/qa-fishing-cast-input.cjs` 检查 220/550/990 ms 的按住时长，在 200 ms 状态延迟与 400 ms 松键传输延迟下保持抛竿预览与实际落点一致。单元测试另外覆盖 144 Hz 下的 60 Hz 动画调度、未召出鱼竿休眠、首次账户初始化、120 次实时快照不重显/移动原生窗口，以及隐藏期间不发送快照。

全量测试首次运行 1448 项，1447 项通过，唯一失败为渲染器修改后的图鉴源版本校验；已用正式构建脚本重建图鉴并复测相关测试。原生窗口逻辑测试 61 项通过。修改后相关测试与截图记录位于 `output/fishing-smoothness/`。

原生 Electron 自动实测未能完成：默认 GPU 子进程在当前测试环境退出，兼容启动也在渲染器初始化阶段超时。保留 `dev/qa-fishing-desktop.cjs --smoothness`，用于可正常启动 Electron 的环境验证真实窗口边界与隐藏后 RAF 停止；本次不把原生实测列为已通过。没有修改发布包或用户存档。
