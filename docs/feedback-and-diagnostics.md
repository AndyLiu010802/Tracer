# 应用内反馈与诊断

日期：2026-09-28。对应商业化计划 B06 的本地反馈部分。

## 使用方式

顶部点击「反馈 / Feedback」，选择问题、功能建议或使用疑问，填写描述；需要时展开复现步骤与预期结果。游客也可使用，无需注册或配置 AI。

报告会完整显示在只读预览中。用户可以复制报告或下载 UTF-8 JSON，再通过与开发者联系的渠道分享。这里没有配置收件地址或反馈服务，复制和下载不代表已提交。复制受限时保留输入并选中预览，提示手动复制或下载。

每次打开面板生成一个报告 ID 和创建时间；编辑、刷新诊断和重复导出保持该标识。关闭面板会清空草稿及诊断选择，不写入应用存储。面板使用独立原生对话框，不替换任务编辑器。

## 诊断范围

诊断默认关闭。用户勾选后才生成一次快照，后续可点击「刷新诊断快照」更新。报告创建时间不会因刷新快照而改变。

| 内容 | 范围 |
| --- | --- |
| 应用 | 受限版本号、桌面或浏览器运行方式、语言、系统和浏览器类别、窗口宽高 |
| 工作区 | 是否加载、待保存、保存中、冲突、加载失败；任务、项目、笔记和收集项数量 |
| 账户 | 游客或账户模式、切换状态，不含账户标识 |
| 专注 | 是否可用、专注或休息模式、运行和结束状态、保留的历史轮数 |

诊断不包含任务名称与正文、项目名称、笔记内容、账户身份、记录 ID、文件路径、URL、原始浏览器字符串、日志或密钥。模型通过显式白名单生成新对象，导出前再次规范化；未知字段不会进入报告。

用户主动填写的文字会显示在预览中并随报告导出，不执行自动敏感信息识别。描述只去除首尾空白，步骤和预期结果保留原文；每个输入最多 4000 个字符。

账户锁定、切换或空间上下文变化时，不能收集旧空间诊断；面板会移除已有诊断。导出时再次核验，发现变化会先更新预览，要求用户重新核对后点击。仍可填写不附诊断的反馈；真实账户锁定流程也可能关闭面板。

## 实现与格式

- `skins/tracer/feedback-model.js`：纯模型，输出 `format: tracer-feedback`、`version: 1`、`id`、`createdAt`、`type`、`description`、`steps`、`expected`，以及用户选择的 `diagnostics`。
- `skins/tracer/feedback.js` / `feedback.css`：中英文面板、预览、复制与下载。诊断只读取当前状态，不改写工作区或专注记录，不新增上传请求。
- `skins/tracer/index.html`：加载资源并增加顶部入口。
- `server.js`：仅在 Tracer 首页注入经过限制的版本号，不暴露其他包信息或配置。

关闭后的异步复制回调不会恢复已清空的内容或改写下一次打开的面板。下载文件与点击时的完整预览一致。
