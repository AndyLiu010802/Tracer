# 流畅度与 macOS 兼容性检查

日期：2026-09-23。检查对象为当前工作区源码，未发布安装包。测试均使用独立临时工作区，不读取或修改日常使用的账户、笔记和收藏。

## 已修复的负担来源

| 来源 | 影响 | 调整 |
| --- | --- | --- |
| 专注模块每 500 ms 重写每日卡片、计时器并刷新家园 | 空闲页面仍反复产生 DOM 修改、布局及统计计算 | 按实际显示值更新；倒计时跨秒更新，日期、语言、设置和内容变化即时更新 |
| 每次按键/点击都读取并解析完整专注历史 | 历史积累后会增加打字时的同步工作 | 输入计数使用内存状态；跨窗口仍通过 storage 事件同步，结算时在原有锁内重新读取存档 |
| 贴纸监听整个 body，并定期无条件刷新 | 与 Note 无关的界面修改也触发贴纸布局 | 监听范围缩到 Note；轮询仅在账本或语言变化时安排刷新，隐藏窗口停止视觉更新 |
| Electron 主窗口关闭 backgroundThrottling 后仍报告页面可见 | 最小化/托盘隐藏时，壁纸、材质及其他动画继续消耗资源 | 通过受限 IPC 同步原生窗口可见性；暂停视觉调度与 CSS 动画，专注结算、保存和提醒继续运行 |
| 隐藏桌宠窗口仍禁用后台节流 | 不可见桌宠继续保持高频调度 | 桌宠窗口恢复系统后台节流；主窗口照常负责状态、提醒和后台工作 |
| 伙伴标签重复赋值 | 没有变化也替换文本节点 | 相同文本不再重复写入；实际伙伴操作仍刷新家园 |

窗口显示状态与焦点分开处理：切换到别的软件但 Tracer 仍显示时，不会把可见动画全部停掉。原生 `hide`、`minimize`、`restore`、`show` 负责暂停和恢复。Electron 官方说明关闭后台节流后 `document.visibilityState` 可能一直为 visible，因此不能只依赖原来的 document.hidden 判断。[Electron BrowserWindow 文档](https://www.electronjs.org/docs/latest/api/browser-window#page-visibility)

未改变动态壁纸的绘制内容、分辨率和播放速度，也没有删除贴纸或材质效果。

## 可复现测量

`dev/audit-performance.cjs` 使用 Edge 无头浏览器、1440×1000 视口、150 个任务和一篇笔记；每个分区稳定后采样 4 秒。记录 DOM MutationObserver 事件和 Chromium Performance 指标。原始前后数据见 `performance-audit-results.json`。

| 分区 | DOM 修改次数：之前 → 之后 | 脚本执行耗时：之前 → 之后 |
| --- | --- | --- |
| 收集箱 | 654 → 28 | 5 ms → 2 ms |
| Note | 700 → 28 | 7 ms → 1 ms |
| 家园 | 1,690 → 28 | 13 ms → 2 ms |
| 商店 | 2,886 → 28 | 12 ms → 1 ms |

这是空闲界面工作量的对比，不是实际设备 FPS、GPU 功耗或整机 CPU 占用的保证；短时间 CPU 数据会受到缓存、垃圾回收和系统调度影响。测试数据不含大量种植动画和长篇笔记，不能代表所有使用规模。

## 验证

- 全量核心及桌面测试：660 通过，0 失败。包括新增原生可见性同步测试、隐藏后动画暂停/恢复与监听释放、输入不重复读取存储的回归检查。
- `dev/qa-desktop-lifecycle.cjs`：Windows x64 原生 Electron 启动、笔记保存/快捷键/重载、最小化暂停动态壁纸与材质、后台专注完成、托盘隐藏与恢复。
- `dev/qa-account-desktop.cjs`：原生账户注册、恢复码页面暂停桌宠、账户和游客隔离、桌宠账户切换。
- `dev/qa-stickers.cjs`：Note 专属悬浮背包、八方向缩放、旋转、取消、保存重试、移动端布局和账户隔离。
- `dev/qa-garden-store.cjs`：独立商店、30 款壁纸/材质预览、家具六向旋转、购买与余额、伙伴拖动、保存重试、持久化和双语布局。

既有同步客户端测试的 DOM 替身缺少 `classList.contains`，导致 16 项测试抛异常；已补齐替身，原有存档恢复断言全部保留。动画释放测试也已覆盖新增的原生可见性监听，而不是移除生命周期断言。

## Mac 状态与边界

当前 Electron 44 要求 macOS 13 Ventura 或更新版本，已在 `build.mac.minimumSystemVersion` 明确写入。Apple Silicon 与 Intel 分别使用 arm64 和 x64 的原生运行时；原有原生菜单、Command 快捷键、Dock 恢复、只读安装目录外的数据路径和可拒绝的输入权限处理保持有效。[Electron 44 系统支持说明](https://www.electronjs.org/blog/electron-44-0)

新增 `.github/workflows/desktop-checks.yml`，PR 或手动触发后在 Windows x64、Mac arm64、Mac x64 上执行测试。两种 Mac 还会原生构建 DMG/ZIP，检查包内资源、签名、可执行文件架构和启动，再对打包后的应用运行桌面生命周期测试。该流程不会发布安装包。

**本次在 Windows 环境执行，Mac 工作流尚未运行，不能宣称本次源码已通过 Mac 实机验收。** Developer ID 签名与 Apple 公证、真实账号 AI 登录、声音和系统权限仍需依照 `macos-install.md` 完成发行验收；配置检查不替代这些结果。

## 仍然有成本的功能

- 实时动态壁纸、水晶折射和花园动画在可见时需要 CPU/GPU；现在隐藏时暂停，保留前台效果。系统减少动态效果及原有暂停控制仍有效。
- 素材目录约 769 MiB，音乐目录约 371 MiB（源码文件合计，非安装包压缩体积或运行内存）。这些主要影响分发、磁盘占用和首次加载；没有为减小数字而删掉现有内容。音乐已经使用分段流式播放，伙伴和星球缓存已有上限。
- 工作区保存仍按完整快照验证、合并和保留恢复草稿。大规模工作区可能增加序列化开销；本次保持数据恢复机制，未未经测量就改变存档格式或降低恢复保障。
